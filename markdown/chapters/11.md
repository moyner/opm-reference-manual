# SUMMARY SECTION


## Introduction

The [SUMMARY](#kw-SUMMARY) section defines the variables to be written to the summary files that are used to generate line graphs of properties such as oil flow rate versus time, grid block pressure versus time, etc. Unlike the other sections, the [SUMMARY](#kw-SUMMARY) section has basically two types of keywords: keywords that request a variable to be written out to the summary file as described in section 11.2 Data Requirements, and the conventional type of keyword described in section 11.3 Keyword Definitions that perform an action. There are literally hundreds of keywords associated with the former indicating the variety of data that can be written to the summary file. Whereas, for the latter there are less than twenty keywords.

Standard summary file output consists of three files as outlined in @tbl-11-1, with the raw requested data stored in [SUMMARY](#kw-SUMMARY) index and [SUMMARY](#kw-SUMMARY) data files, the [SUMMARY](#kw-SUMMARY) RSM file is an ASCII file that is generated from the other two files by the simulator at the end of the run. There is also the option to output an OPM Flow specific Enhanced [SUMMARY](#kw-SUMMARY) output file.


| File Type | Data Type | Description | OPM Flow Status |
| --- | --- | :------ | --- |
| ESMRY | Dynamic Vector Data | This is an OPM FLOW specific Enhanced [SUMMARY](#kw-SUMMARY)  (*.ESMRY) output file format that is optimized for fast loading of selected vectors by post-processing applications. The *.ESMRY file is re-written for every time step and does not have a performance impact on the simulation. Load times are in the order of 30 times faster compared with fetching selected vectors using the *.UNSMRY file format in post processing software. The file type is compatible with OPM ResInsight and the option is activated via the --enable-esmry=true command line option (true is the default value). Note that the [FMTOUT](#kw-FMTOUT),  [MULTOUT](#kw-MULTOUT), and [UNIFOUT](#kw-UNIFOUT) keywords have no impact on this file type. | OPM Flow Fully Supported. |
| RSM | Output File | The RSM file contains the variables requested to be written to the [SUMMARY](#kw-SUMMARY) file via the keywords described in the 11.2 Data Requirements, in a tabulated ASCII output format. The format of the file enables the data to be easily loaded into the LibreOffice Calc program for further processing, as each vector represents one column. The report is written at the end of the simulation run by parsing the [SUMMARY](#kw-SUMMARY) Index and [SUMMARY](#kw-SUMMARY) Data files. | Fully Supported |
| [SUMMARY](#kw-SUMMARY) Index | Dynamic Vector Index | The [SUMMARY](#kw-SUMMARY) index file type specifies and defines the format and data type written to the [SUMMARY](#kw-SUMMARY) Data file. | Fully Supported |
| [SUMMARY](#kw-SUMMARY) Data | Dynamic Vector Data | The [SUMMARY](#kw-SUMMARY) data file contains the variables requested to be written to the file via the keywords described in the 11.2 Data Requirements. The data consists of vectors that are used to generate line graphs of properties such as oil flow rate versus time, grid block pressure versus time, etc. The properties to be stored on the [SUMMARY](#kw-SUMMARY) file are written to the summary file at the end of each successful time step. The data can be used to compare actual production data with the simulation derived results in post processing software like OPM ResInsight. | Fully Supported |
| Notes: |  |  |  |
: OPM Flow Summary Output File Summary {#tbl-11-1}
As mentioned in @tbl-11-1 all files can be written out in either ASCII or binary formats and in addition the [SUMMARY](#kw-SUMMARY) file can be loaded or written out in either unified or non-unified formats.  The file type (ASCII or binary) and file structure format (unified or non-unified formats) is set via a set of keywords in the [RUNSPEC](#kw-RUNSPEC) section, as described in @tbl-11-2 for easy of reference.


| Process | [RUNSPEC](#kw-RUNSPEC) Keyword | Description | Files |
| --- | --- | :------ | --- |
| Input | [FMTIN](#kw-FMTIN) | The keyword defines the input files to be formatted as ASCII, i.e., text files, as opposed to binary files. | *.FSMSPEC *.FUNSMRY |
| [MULTIN](#kw-MULTIN) | The keyword defines the input files to be non-unified multiple files, as opposed to unified files. | *.SMSPEC *.S0001 |  |
| [UNIFIN](#kw-UNIFIN) | [UNIFIN](#kw-UNIFIN) defines the input files to be unified files, as opposed to non-unified multiple files. | *.SMSPEC *.UNSMRY |  |
| Output | [FMTOUT](#kw-FMTOUT) | The keyword sets all output files to be formatted as ASCII, i.e., text files, as opposed to binary files. | *.FSMSPEC *.FUNSMRY |
| [MULTOUT](#kw-MULTOUT) | [MULTOUT](#kw-MULTOUT) defines the output files to be non-unified multiple files, as opposed to unified files. | *.SMSPEC *.S0001 |  |
| [UNIFOUT](#kw-UNIFOUT) | [UNIFOUT](#kw-UNIFOUT) defines the output files to be unified files, as opposed to non-unified multiple files. | *.SMSPEC *.UNSMRY |  |
: RUNSPEC Input and Output File Format Keywords {#tbl-11-2}
OPM Flow automatically generates the [SUMMARY](#kw-SUMMARY) file names based on the input file name and the output options selected via the keywords in the [RUNSPEC](#kw-RUNSPEC) section as summarized in in @tbl-11-2.  For example, starting OPM Flow using the following command from the terminal:


```
flow CASENAME
```


will start the simulator and run the case specified by CASENAME.DATA. Here CASENAME is the “root” of the filename and DATA is the extension of the filename.  OPM Flow will generate the [SUMMARY](#kw-SUMMARY) output files based on the CASENAME with the extension based on the type (ASCII or binary) and file structure format (unified or non-unified formats), as outlined in @tbl-11-3.


| File Type | Unformatted Extension | Description | Formatted Extension |
| --- | --- | :------ | --- |
| RSM | *.RSM | Output RSM file. | *.RSM |
| [SUMMARY](#kw-SUMMARY) Index | *.SMSPEC | The [SUMMARY](#kw-SUMMARY) index file for both unified and non-unified formats. | *.FSMSPEC |
| [SUMMARY](#kw-SUMMARY) Data Non-Unified | *.Snnnn | The [SUMMARY](#kw-SUMMARY) data files containing the variables requested to be written to the [SUMMARY](#kw-SUMMARY) files. For example, the [SUMMARY](#kw-SUMMARY) non-unified binary files would be: CASENAME.S0001 CASENAME.S0002 CASENAME.S0003 etc. CASENAME.SMSPEC | *.Annnn |
| [SUMMARY](#kw-SUMMARY) Data Unified | *.UNSMRY | The [SUMMARY](#kw-SUMMARY) data file containing the variables requested to be written to the [SUMMARY](#kw-SUMMARY) file. For example, the [SUMMARY](#kw-SUMMARY) data unified binary files: CASENAME.UNSMRY CASENAME.SMSPEC | *.FUNSMRY |
| Notes: |  |  |  |
: OPM Flow File Naming Conventions {#tbl-11-3}
The default behavior is to write out the requested variables at each time step. As this can lead to large files (or a large number of files for non-unified output), especially for full field simulation models, the [RPTONLY](#kw-RPTONLY) - Activate the Report Time Steps Only Option for the [SUMMARY](#kw-SUMMARY) File keyword allows one to write out the data only at a report time step instead.

The [SUMMARY](#kw-SUMMARY) section is terminated by the [SCHEDULE](#kw-SCHEDULE) keyword.
